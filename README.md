# ⚽ Football Simulator

Браузерный футбольный симулятор на чистом JavaScript с тактическим ИИ, 
прессингом, построением пути, физикой мяча и визуальным редактором 
расстановки игроков.

## 📌 О проекте

Игра **формируется и рассчитывается онлайн** — каждый кадр матча 
вычисляется прямо в браузере в реальном времени. Никакой предварительной 
записи или реплея: движение игроков, пасы, удары, прессинг и физика 
мяча рассчитываются на лету в игровом цикле (`requestAnimationFrame`).

Все тактические данные (расстановка, зоны, действия, скиллы) хранятся 
в базе данных и загружаются через PHP API. Редактор позволяет настраивать 
команду визуально и сохранять изменения обратно в БД.

## 🎯 Что реализовано

### 🧠 Игровой движок

- **Тактическая сетка 13×13** — поле разбито на 169 зон, каждая позиция 
  привязана к конкретной зоне.
- **Три фазы игры** — оборона / переход / атака для каждой команды 
  отдельно, с задержкой при выходе из обороны (`defense_exit_speed`).
- **Действия с мячом** — 16 типов действий, каждое со своими весами 
  для каждой фазы: `pass`, `short_pass`, `long_pass_forward`, `cross`, 
  `through`, `switch`, `fast_pass`, `diagonal`, `pass_to_gk`, 
  `pass_to_defender`, `dribbling`, `speed_dribbling`, `hold`, 
  `fall_back`, `shoot`, `clearance`.
- **Действия без мяча** — 4 типа: `press_ball` (прессинг владельца), 
  `cover_presser` (страховать прессингующего), `pressing` (накрывать 
  ближайшего соперника), `fall_back` (отходить назад).
- **Выбор действия по формуле** — `weight = personality × playerWeight + 
  (1 - personality) × teamWeight`, затем рулетка с порогом `diff > 0.18`.
- **Учёт IQ** — интервал между решениями игрока зависит от IQ 
  (IQ 100 → 200 мс, IQ 0 → 1200 мс).
- **Учёт `passCount`** — количество линий паса (видимых партнёров) 
  зависит от IQ и настраивается в редакторе (1–7).

### 🎮 Система пасов

- **Короткий пас** — ближайший партнёр.
- **Длинный пас вперёд** — самый дальний партнёр впереди.
- **Диагональный пас** — с сужением к центру и упреждением движения.
- **Прострел** — низом в штрафную.
- **Навес** — верхом в штрафную с анимацией полёта.
- **Смена фланга** — на противоположный фланг.
- **Пас защитнику / вратарю** — назад.
- **Конус точности** — зависит от `passing` (от 3° до 60°).
- **Ограничение по силе** — `power` определяет максимальную дальность.
- **Упреждение принимающего** — учёт `lastX/lastY` для расчёта точки 
  прилёта.

### 🏃 Дриблинг и путь

- **Построение пути** — обход соперников (радиус 40px) и партнёров 
  (радиус 30px) через перпендикулярный сдвиг.
- **Прямой путь в дриблинге** — без обхода (напролом).
- **Замедление при дриблинге** — визуальный эффект «слоу-мо» 
  с глобальным множителем скорости (0.35) и виньеткой.
- **Бег к свободному мячу** — игрок бежит к мячу по красной линии.

### 🔴 Прессинг

- **Контроллер прессинга** (`pressController.js`) — каждые полкадра 
  назначает прессингующего и страхующего в квадрате 200×200 вокруг мяча.
- **Перехват на линии движения владельца** — расчёт точки пересечения 
  траектории прессингующего с линией движения владельца мяча (из 
  `player.path` или вектора `lastMoveX/lastMoveY`).
- **Кулдаун после смены** — 5000 мс.
- **Время преследования** — зависит от прогресса атаки (1000–3000 мс).
- **Страховка владельца мяча** — центральные защитники (LCD/CD/PCD) 
  выдвигаются вперёд при потере.
- **Роли без мяча** — `pressing` (накрывать) и `fall_back` (страховать) 
  с автоматическим выбором цели-угрозы.

### ⚽ Физика мяча

- **Удар** — с торможением (`shotDeceleration = 0.985`), максимальной 
  дальностью (зависит от `power`) и конусом точности (от `finishing`).
- **Навес** — верховая траектория с анимацией полёта (парабола), 
  тенью и увеличением спрайта.
- **Отскок после отбора** — мяч летит 35px со скоростью 1 и 
  останавливается.
- **Свободный мяч** — с плавным замедлением.

### 🎨 Редактор расстановки (`editor.html`)

- **Drag-and-drop игроков** по зонам поля.
- **Три фазы на игрока** — атака (🟢), переход (🟡), оборона (🔴).
- **Назначение движения** — клик по полю задаёт целевую зону 
  для текущей фазы.
- **Действия с мячом** — ползунки весов 0–100 для каждой фазы, 
  drag-and-drop для смены приоритета.
- **Действия без мяча** — прессинг, страхование, накрывание.
- **Связанные пары** — `dribbling ↔ hold` (сумма 100), 
  `speed_dribbling ↔ hold` (сумма 100).
- **Ближайшие игроки (passCount)** — слайдер 1–7 с ограничением по IQ.
- **Скиллы** — визуализация всех 13 характеристик + характер.
- **Линии фаз** — перетаскивание границ обороны/перехода прямо на поле.
- **Командные приоритеты** — движение/пас/удар для каждой фазы.
- **Скорость выхода из обороны** — 0–5 (задержка 0–5000 мс).
- **Сохранение в БД** — одной кнопкой «Сохранить всё».

### 🗄️ База данных и API

- **`load.php?team_id=1|2`** — загрузка позиций, зон, действий, 
  настроек команды.
- **`save.php`** — сохранение всех настроек команды.
- **`load_match.php?id=001`** — загрузка записанных кадров (реплей).

### 🎥 Визуализация

- **3D-эффект стадиона** — CSS `perspective` + `rotateX(15deg)`.
- **Поле** — фон `stad.jpg`, разметка, 3D-ворота с сеткой.
- **Зоны 13×13** — с ID в центре, подсветка безопасной зоны жёлтым.
- **Линии паса** — до ближайших партнёров (кол-во = `passCount`).
- **Красные линии** — от мяча к двум ближайшим игрокам (борьба).
- **Жёлтый путь** — построенный путь владельца мяча.
- **Синие линии удара** — конус точности удара.
- **Круги прессинга** — красный `P` (прессингующий) и синий `C` 
  (страхующий), серый пунктир — кулдаун.
- **Тактические зоны из БД** — синие (A) и красные (B) точки.
- **Фазы команд** — заливка зон поля в зависимости от фазы.
- **Реплей** (`match_player.js`) — воспроизведение кадров из БД 
  с наложением на ту же отрисовку.

## 🧠 Как работает ИИ (подробно)

### 1. Определение фазы игры

Фаза определяется по позиции мяча относительно линий фаз 
(`PHASE_LINE_1`, `PHASE_LINE_2`) с корректировкой на владение:

| Позиция мяча | Мяч у своей команды | Мяч у соперника |
|--------------|---------------------|-----------------|
| Оборона      | transition          | defensive       |
| Переход      | attack              | defensive       |
| Атака        | attack              | transition      |

При переходе `defensive → transition` действует **задержка** 
(`defense_exit_speed` из БД, от 0 до 5000 мс), чтобы команда не 
«прыгала» в атаку мгновенно.

### 2. Выбор действия с мячом

Игрок с мячом выбирает действие из `phaseActions[фаза]` по формуле:
weight = personality × playerWeight + (1 - personality) × teamWeight


Где:
- `personality` — от 1 до 10 (эгоист → послушный),
- `playerWeight` — индивидуальные веса игрока,
- `teamWeight` — командные приоритеты.

Затем — рулетка по весам с порогом `diff > 0.18` (если явный лидер — 
берём его, иначе — случайно по вероятностям).

### 3. Выбор действия без мяча

Игрок без мяча выбирает из `responsibleActions[фаза]`:
- `press_ball` — прессинг владельца,
- `cover_presser` — страховать прессингующего,
- `pressing` — накрывать ближайшего соперника,
- `fall_back` — отходить назад.

### 4. Прессинг и перехват

`pressController.js` каждые полкадра:
1. Находит кандидатов в квадрате 200×200 вокруг зоны мяча.
2. Назначает прессингующего (ближайшего) и страхующего.
3. `updatePress` считает **точку перехвата** на линии движения 
   владельца (из `player.path` или вектора `lastMoveX/lastMoveY`).
4. Решает квадратное уравнение для нахождения времени встречи.

### 5. Построение пути

`pathfinding.js` строит ломаную от мяча до целевой тактической зоны, 
обходя соперников (радиус 40px) и партнёров (радиус 30px) через 
перпендикулярный сдвиг. Если игрок в дриблинге — путь строится напрямую.
